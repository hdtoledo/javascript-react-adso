¿Por qué este JavaScript es el 90% del éxito en React?

10% React API · 90% JS ES6+
El Mito de la "Sintaxis Mágica":

Muchos aprendices creen que React es un lenguaje de programación nuevo con sintaxis misteriosa. La realidad es que React no inventó un lenguaje: es una librería donde el 90% es JavaScript moderno (ES6+) estándar.

El Error Fatal al saltar a React:

Intentar manipular el DOM con document.getElementById() o mutar arreglos con .push(). React mantiene su propia copia virtual de la interfaz; si alteras el DOM a sus espaldas, tus cambios se perderán en el próximo renderizado.

Módulo 1 · Lección 01 (Paso 2 de 7) Paradigmas de Programación Web

Paradigma Imperativo vs Declarativo (UI = f(Estado))

UI = f(Estado)
💡 La Ecuación Universal de React: UI = f( Estado )

La interfaz de usuario (UI) nunca se manipula a mano. La pantalla es el resultado de una función matemática (f) evaluada con los datos actuales (Estado). Si cambias el estado, la pantalla se redibuja sola de forma predecible.

Caso Real en Aula: Sistema de Registro de Asistencia en el CADPH Garzón
1. Vanilla JS (Imperativo - El "CÓMO") 10 líneas · Propenso a Desincronización 
// Buscar elementos a mano
const btn = document.getElementById('btn');
btn.addEventListener('click', () => {
  const ul = document.getElementById('lista');
  const li = document.createElement('li');
  li.textContent = 'Carlos Huila';
  ul.appendChild(li);

  // Peligro: Sincronizar contador a mano
  const total = document.getElementById('total');
  total.innerText = parseInt(total.innerText) + 1;
});

¿Cuál es el problema real? Si un aprendiz borra un registro y olvidas restar el contador en otra línea de código, el contador dirá "Total: 10" pero habrá 9 aprendices en la lista.

2. React + Vite (Declarativo - El "QUÉ") 4 líneas · 100% Sincronizado 
// Estado reactivo en memoria
const [asistentes, setAsistentes] = useState(['Ana', 'David']);

return (
  <div>
    <p>Total presentes: {asistentes.length}</p>
    <ul>{asistentes.map(a => <li key={a}>{a}</li>)}</ul>
    <button onClick={() => setAsistentes([...asistentes, 'Carlos'])}>
      Registrar
    </button>
  </div>
);

¿Por qué es superior? El contador {asistentes.length} y la lista están enlazados matemáticamente. Es imposible que se desincronicen.

Regla de oro: Nunca uses document.querySelector ni innerHTML dentro de React; rompe el árbol de Fiber y causa fugas de memoria.

Módulo 1 · Lección 01 (Paso 3 de 7) Arquitectura Interna de React

El Virtual DOM y el Motor de Reconciliación (Fiber)

Algoritmo de Diffing en RAM
🐢 ¿Por qué el DOM del Navegador es Lento?

El DOM del navegador está escrito en C++ dentro del motor Chromium/Gecko. Cada vez que modificas el HTML con Vanilla JS, el navegador ejecuta dos tareas muy pesadas:

Reflow: Recalcular tamaño y posición de cada caja.
Repaint: Volver a pintar los píxeles en la pantalla.
⚡ La Solución: Virtual DOM en Memoria RAM

El Virtual DOM es una copia ligera en JavaScript (un árbol de objetos JSON normales). Crear y comparar objetos en la memoria RAM de JavaScript toma menos de 0.3 milisegundos.

CICLO DE RECONCILIACIÓN (FIBER) EN 4 PASOS:
1
Disparo de Estado: El usuario hace clic y se ejecuta setState(nuevoValor).
2
Nuevo Virtual DOM: React construye un nuevo árbol virtual en memoria RAM en 0.2ms.
3
Diffing (Comparación): Compara el árbol viejo vs el nuevo y halla la diferencia mínima exacta.
4
Commit Atómico: Solo muta el nodo exacto (node.nodeValue) en el DOM real sin redibujar todo.
📌 Caso Real: ¿Por qué en Vanilla JS se borra lo que escribe el aprendiz?

Si tienes un formulario de 10 campos y agregas una alerta con contenedor.innerHTML += '<div class="alerta">Guardado</div>', el navegador destruye todo el árbol de inputs y lo crea de nuevo: el aprendiz pierde todo lo que había escrito y el cursor se sale del campo. En React con Virtual DOM, el algoritmo de Diffing deja los 10 inputs intactos y solo inserta la alerta.

Inmutabilidad en Memoria: .push() vs [...spread]

Object.is(prev, next)
🧠 ¿Cómo decide React si re-renderiza o no?

React no recorre los 500 elementos de una lista para ver si cambió algo (eso quemaría la CPU). En su lugar, hace una comprobación ultrarrápida de referencia:

Object.is(estadoAnterior, nuevoEstado)

Si las dos variables apuntan a la misma dirección de memoria en el Heap, React asume que nada cambió y cancela el renderizado.

❌ El Bug #1 del Aprendiz de ADSO: 
const [items, setItems] = useState(['A', 'B']); // Memoria: 0x004F
items.push('C'); // Mutó en la misma celda 0x004F!
setItems(items); // Object.is(0x004F, 0x004F) === true -> ¡NO RENDERIZA!

"Instructor, mi console.log muestra 3 elementos, pero la pantalla sigue mostrando 2. ¿Por qué?" Porque mutaste con .push() sin cambiar la referencia de memoria.

✅ LA SOLUCIÓN: SPREAD OPERATOR ([...spread]) 
// Genera un NUEVO arreglo en otra celda de memoria
setItems(prev => [...prev, 'C']); // Nueva celda: 0x009A

// Comprobación interna de React:
Object.is(0x004F, 0x009A) === false; // ¡CAMBIO DETECTADO!
// -> Dispara Fiber Diffing y actualiza la pantalla
Comparativa de Operadores:
• .push() / .splice(): Mutan el arreglo original (Prohibidos en React).
• [...arr, item] / .filter() / .map(): Crean copias inmutables (Obligatorios en React).
💡 La inmutabilidad permite que React viaje en el tiempo y mantenga historial de estados.

Native ESM + esbuild (Go)
📦 ¿Qué es un Bundler (Empaquetador)?

El navegador no sabe qué es un archivo .jsx ni cómo importar módulos de node_modules. El empaquetador procesa, optimiza y sirve los archivos al navegador.

💀 La Muerte de Create React App (CRA / Webpack):

CRA utilizaba Webpack. Antes de poder ver un solo botón en pantalla, Webpack tenía que empaquetar todos los archivos del proyecto en memoria. En las salas de sistemas del SENA, tardaba entre 40 y 90 segundos solo en levantar el servidor. Hoy en día, CRA está oficialmente descontinuado por el equipo de React.

⚡ La Revolución de Vite (Francés para "Rápido"):
  • • Native ES Modules (ESM): El navegador descarga solo el archivo que necesita en el momento.
  • • Compilador en Go (esbuild): Entre 10 y 100 veces más rápido que compiladores JS.
  • • HMR en menos de 20ms: Guardas en VS Code y el cambio se ve instantáneamente.

Variables Modernas: Inmutabilidad vs Reasignación

const vs let (La muerte de var)
¿Por qué var está prohibido en React y JS moderno?

var NO respeta bloques {} (como sentencias if o bucles for). Se escapa al ámbito global de la ventana, sobreescribe variables con el mismo nombre y sufre de hoisting (existe como undefined antes de su línea de creación).

let y const: Ámbito Léxico de Bloque

Solo existen dentro de las llaves { ... } donde fueron creadas. En bucles asíncronos (como peticiones a una API o temporizadores), cada vuelta del bucle crea su propio enlace léxico en memoria.

LABORATORIO EN VIVO: EL CLÁSICO BUCLE FOR Prueba en Línea 
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log("Turno aprendiz:", i);
  }, 100);
}
📟 Salida de Consola:
Presiona "Probar con var" o "Probar con let" para ver la diferencia de memoria...
❓ La Gran Duda del Aprendiz:

"Instructor, si declaré const aprendiz = { ... }, ¿por qué puedo cambiar aprendiz.nombre = 'Ana' sin que JavaScript me dé error?"

🧠 La Explicación Técnica (Stack vs Heap):
1. Stack (Pila): Guarda la variable y su puntero o dirección de memoria (0x004F). const solo protege este puntero. No puedes cambiar la dirección.
2. Heap (Montículo): Guarda los datos reales del objeto. Como modificar una propiedad no cambia el puntero en el Stack, JavaScript lo permite.
⚠️ El peligro en React: Aunque JS te permita mutar el objeto en el Heap, React compara los punteros del Stack. Como el puntero no cambió, ¡React NO redibuja la pantalla!
EXPERIMENTO: ¿QUÉ PERMITE CONST? Ejecutor en Vivo 
const aprendiz = { id: 3314621, nombre: "David Huila" };
// Puntero en Stack: 0x004F

// Experimento 1: Reasignar todo el objeto
aprendiz = { id: 9999999 };

// Experimento 2: Mutar una propiedad interna
aprendiz.nombre = "Ana María";

🚨 La Trampa del Spread Superficial (Shallow Copy):

El operador spread { ...objeto } SOLO clona las propiedades de primer nivel. Si el objeto contiene objetos anidados (como contacto: { tel, ciudad }), la copia sigue compartiendo la misma dirección de memoria del objeto anidado.

⭐ La Solución: Propagación Anidada (Deep Spread):

Para actualizar un dato anidado sin mutar el original, debemos propagar el nivel exterior Y también el nivel anidado: 

const actualizado = {
  ...aprendiz,
  contacto: {
    ...aprendiz.contacto,
    tel: "3208889999"
  }
};

Desestructuración: La Anatomía de las Props en React

Reto 1 en Aula

La desestructuración permite "desempaquetar" propiedades de objetos directamente en variables con una sintaxis limpia, eliminando la necesidad de escribir props.titulo, props.precio repetidamente.

Tres superpoderes indispensables para React:

  • 1. Renombrar propiedades: const { correo: email } = aprendiz; (cambia el nombre de la variable al extraerla).
  • 2. Valores por defecto (fallback): const { ficha = 3314621 } = aprendiz; (si la propiedad no viene o es undefined).
  • 3. Desestructuración en argumentos: En React, los componentes reciben las props directamente en los parámetros de la función.
TarjetaProducto.jsx (Componente React) Props ES6 
// Desestructuración directa en los parámetros:
function TarjetaProducto({ 
  id, 
  titulo, 
  precio = 0,             // Fallback por defecto
  categoria: rubro = "General" // Renombrado + Fallback
}) {
  return (
    <div className="tarjeta-adso">
      <h3>{titulo}</h3>
      <p>Precio: ${precio}</p>
      <span>Rubro: {rubro}</span>
    </div>
  );
}
💡 Dominar esto te permite escribir componentes limpios sin ensuciar el cuerpo de la función.

Lección 04 / El Operador Spread

Spread Operator (...): El Motor de useState

Reto 2 en Aula

El operador de propagación (spread operator) expande un iterable (array u objeto) en lugares donde se esperan elementos clave-valor o listas.

Clonado inmutable de Objetos

Copia superficial de todas las propiedades previas y sobreescritura de las que necesitemos cambiar.

Inserción en Arreglos sin .push()

[...carrito, nuevoProducto] crea un nuevo arreglo con el nuevo elemento al final sin tocar el anterior.

spread-en-react.js 
// 1. Agregar al carrito inmutablemente
const agregarItem = (carrito, item) => [...carrito, item];

// 2. Modificar propiedad de objeto
const actualizarTema = (config, nuevoTema) => ({
  ...config,
  tema: nuevoTema,
  ultimaModificacion: Date.now()
});

// 3. Modificar un item dentro de una lista por ID
const marcarCompletado = (tareas, id) =>
  tareas.map(t => t.id === id ? { ...t, completada: true } : t);
👉 Dominando esto, el hook useState de React será natural y sin bugs.
🎯 Ejercicio en Aula 04: Carrito de Compras Inmutable (Reto 2) Reto 2 en Vivo (10 min)

// Inserción sin push:
const agregar = (carrito, item) => [...carrito, item];
// Borrado inmutable por ID:
const eliminar = (carrito, id) => carrito.filter(item => item.id !== id);
Lección 05 / Funciones Flecha

Arrow Functions y Retorno Implícito

Sintaxis Limpia

Las funciones flecha no solo son más cortas de escribir; en React son indispensables para manejadores de eventos en línea y transformación de datos.

Puntos Clave:
  • ✔️ Retorno implícito de una sola línea: const doble = n => n * 2;
  • ✔️ Retorno implícito de objetos con paréntesis: () => ({ id: 1, activo: true })
  • ✔️ No poseen su propio this (heredan el contexto léxico).
Ojo en React: <button onClick={hacerAlgo}> pasa la referencia. Si necesitas pasar argumentos, usa flecha: <button onClick={() => eliminar(id)}>.
arrow-functions.js 
// Función tradicional:
function sumarTradicional(a, b) {
  return a + b;
}

// Arrow function moderna concisa:
const sumar = (a, b) => a + b;

// Retorno implícito de componente o entidad:
const crearAprendiz = (id, nombre) => ({
  id,
  nombre,
  ficha: 3314621,
  creadoEn: new Date().toISOString()
});

Lección 07 / Acumuladores Complejos

Dominio de .reduce(): Balances y useReducer

Reto 4 en Aula

Mientras que map y filter devuelven nuevos arreglos, .reduce() permite condensar una colección en cualquier estructura: un número, un objeto agrupador, un mapa de totales, o un estado global.

Firma del método: array.reduce((acumulador, elementoActual) => { ... }, valorInicial)

const totalNeto = carrito.reduce((acc, item) => {
  return acc + (item.precio * item.cantidad);

🎯 Ejercicio en Aula 07: Balance Financiero con IVA 19% (Reto 4) Reto 4 en Vivo (10 min)

Reto para el aprendiz: A partir de una lista de órdenes con precio, cantidad y porcentaje de descuento, calcula con un solo .reduce() el balance total: subtotal bruto, descuentos aplicados, base gravable e IVA 19%. 

const balance = items.reduce((acc, item) => {
  const bruto = item.precio * item.cantidad;
  const desc = bruto * (item.descuento || 0);
  acc.subtotal += bruto;
  acc.descuentos += desc;
  return acc;
}, { subtotal: 0, descuentos: 0 });
balance.baseGravable = balance.subtotal - balance.descuentos;
balance.iva19 = Math.round(balance.baseGravable * 0.19);
balance.totalPagar = balance.baseGravable + balance.iva19;

Lección 10 / Peticiones de Datos

Async / Await con Control Robusto de Fallos

Reto 5 en Aula

Toda interacción con bases de datos o servicios externos en la nube toma tiempo. Con async/await escribimos código asíncrono que se lee secuencialmente como sincrónico.

❌ Nunca olvides el bloque try / catch:

Si la red se cae o el servidor devuelve error 500 y no hay catch, la aplicación en React se congela o lanza una excepción fatal no controlada.

En el Reto 5 implementamos un Pipeline Seguro con Fallback: si la API falla, la función devuelve datos seguros por defecto y no rompe el flujo del cliente.

consumo-api.js Patrón Profesional 
async function cargarDatosServidor(endpoint, fallback = []) {
  try {
    const res = await fetch(endpoint);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    return { exito: true, data };
  } catch (err) {
    console.error("Error al cargar:", err.message);
    return { exito: false, data: fallback };
  }
}

Lección 11 / Rendimiento Concurrente

Concurrencia: Promise.all() y Promise.allSettled()

Dashboards React

Promise.all([p1, p2, p3])

Ejecuta todas en paralelo. Si UNA SOLA falla, toda la promesa se rechaza de inmediato (todo o nada). Ideal cuando todos los datos son indispensables.

Promise.allSettled([p1, p2, p3])

Espera a que todas terminen, sin importar si triunfaron o fallaron. Devuelve el estado de cada una (fulfilled o rejected). Perfecto para sincronizar múltiples microservicios.

// Cargar en paralelo sin bloquear:
const [usuarios, productos, ventas] = await Promise.all([
  fetch('/api/usuarios').then(r => r.json()),
  fetch('/api/productos').then(r => r.json()),
  fetch('/api/ventas').then(r => r.json())
]);

Lección 01 / Fundamento Teórico

¿Por qué este JavaScript es el 90% del éxito en React?

Mentalidad React

Muchos aprendices creen que React es un lenguaje nuevo con una sintaxis mágica. La realidad es que React es 10% API de librería y 90% JavaScript ES6+ puro.

⚠️ El error más común al saltar a React:

Tratar de manipular el DOM con document.getElementById o mutar arreglos con .push(). En React, la UI es una función directa del estado: UI = f(State).

¿Por qué usaremos Vite en lugar de Create-React-App?

  • ES Modules nativos: Vite no empaqueta todo el código en el arranque, carga módulos bajo demanda.
  • Hot Module Replacement (HMR): Refresca cambios en menos de 50 milisegundos en el navegador.
MATRIZ: JS TRADICIONAL VS REACT + VITE ADSO 3314621
❌ Ciclos for + innerHTML ✔️ datos.map(item => <Card ... />)
❌ estado.push(nuevoElemento) ✔️ setEstado(prev => [...prev, nuevo])
❌ if/else gigante en el template ✔️ operador ternario && y cortocircuito
Tip: Dominar estos 5 patrones te garantiza un 100% de fluidez en React.
🎯 Ejercicio en Aula 01: Identificar Mutación vs Estado Declarativo Práctica en Puesto (5 min)

Reto para el aprendiz: En React, ¿cuál de las siguientes dos funciones provocará que la interfaz gráfica NO se actualice y cuál funcionará correctamente?

// Implementación A: function agregarA(lista, item) {
  lista.push(item);
  return lista;
}
// Implementación B: function agregarB(lista, item) {
  return [...lista, item];
}

✔ Explicación Técnica para el Aula:

La Implementación A es destructiva: .push() muta el arreglo existente en la misma dirección de memoria RAM. Al llamar setLista(agregarA(lista, item)), React ejecuta una comparación de referencia (prev === next), determina que ambas apuntan al mismo espacio en memoria y cancela el re-renderizado.

La Implementación B crea una nueva referencia de memoria con el operador spread ([...lista, item]), lo que le indica a React que el estado cambió y redibuja la interfaz al instante.

Lección 02 / Ámbitos y Memoria

Variables Modernas: Inmutabilidad vs Reasignación

const vs let

En JavaScript moderno, olvidamos por completo la palabra clave var debido a los problemas de hoisting y falta de scope de bloque.

1. const (Regla por defecto - 95% de los casos) No permite reasignación de variable. Si almacena un objeto o array, ¡sus propiedades internas siguen siendo mutables si no tenemos cuidado!
2. let (Solo cuando el valor deba reasignarse) Acumuladores numéricos en bucles, temporizadores o flags que cambian explícitamente.
💡 Regla de Oro en React: React detecta cambios mediante comparación de referencia de memoria (prev !== next). Si mutas un objeto con obj.nombre = 'x', la referencia es la misma y React NO redibuja la pantalla.
ejemplo-inmutabilidad.js 
// ❌ MUTACIÓN PELIGROSA (React no se entera)
const aprendiz = { nombre: 'Juan', promedio: 3.5 };
aprendiz.promedio = 4.2; // Misma dirección en RAM

// ✔️ ACTUALIZACIÓN INMUTABLE (React detecta nuevo estado)
const aprendizActualizado = {
  ...aprendiz,
  promedio: 4.2
};

console.log(aprendiz === aprendizActualizado); // false (Nueva referencia!)

Lección 03 / Sintaxis Clave

Desestructuración: La Anatomía de las Props en React

Reto 1 en Aula

La desestructuración te permite "desempaquetar" valores de arreglos o propiedades de objetos en variables distintas de forma concisa y elegante.

Tres superpoderes de la desestructuración:

  • 1. Renombrar propiedades: const { name: nombreCompleto } = user;
  • 2. Valores por defecto (fallback): const { rol = "Aprendiz" } = user;
  • 3. Desestructuración en argumentos: Evita escribir props.titulo, props.precio en cada línea.

Observa el paralelo en el código de la derecha: cómo luce una función en JavaScript vanilla y cómo se transforma directamente en un componente funcional de React.

Lección 04 / El Operador Spread

Spread Operator (...): El Motor de useState

Reto 2 en Aula

El operador de propagación (spread operator) expande un iterable (array u objeto) en lugares donde se esperan elementos clave-valor o listas.

Clonado inmutable de Objetos

Copia superficial de todas las propiedades previas y sobreescritura de las que necesitemos cambiar.

Inserción en Arreglos sin .push()

[...carrito, nuevoProducto] crea un nuevo arreglo con el nuevo elemento al final sin tocar el anterior.

spread-en-react.js 
// 1. Agregar al carrito inmutablemente
const agregarItem = (carrito, item) => [...carrito, item];

// 2. Modificar propiedad de objeto
const actualizarTema = (config, nuevoTema) => ({
  ...config,
  tema: nuevoTema,
  ultimaModificacion: Date.now()
});

// 3. Modificar un item dentro de una lista por ID
const marcarCompletado = (tareas, id) =>
  tareas.map(t => t.id === id ? { ...t, completada: true } : t);
👉 Dominando esto, el hook useState de React será natural y sin bugs.

Lección 05 / Funciones Flecha

Arrow Functions y Retorno Implícito

Sintaxis Limpia

Las funciones flecha no solo son más cortas de escribir; en React son indispensables para manejadores de eventos en línea y transformación de datos.

Puntos Clave:
  • ✔️ Retorno implícito de una sola línea: const doble = n => n * 2;
  • ✔️ Retorno implícito de objetos con paréntesis: () => ({ id: 1, activo: true })
  • ✔️ No poseen su propio this (heredan el contexto léxico).
Ojo en React: <button onClick={hacerAlgo}> pasa la referencia. Si necesitas pasar argumentos, usa flecha: <button onClick={() => eliminar(id)}>.
arrow-functions.js 
// Función tradicional:
function sumarTradicional(a, b) {
  return a + b;
}

// Arrow function moderna concisa:
const sumar = (a, b) => a + b;

// Retorno implícito de componente o entidad:
const crearAprendiz = (id, nombre) => ({
  id,
  nombre,
  ficha: 3314621,
  creadoEn: new Date().toISOString()
});
🎯 Ejercicio en Aula 05: Refactorización a Retorno Implícito de Objeto Sintaxis Limpia (5 min)

Reto para el aprendiz: ¿Por qué la expresión () => { id: 1 } devuelve undefined en JavaScript, y cómo se corrige usando paréntesis para retornar el objeto implícitamente?

Las llaves {} en una arrow function son interpretadas como el cuerpo de la función (bloque de sentencias), no como un objeto literal. Para indicarle al motor JS que es un objeto retornado en una línea, lo envolvemos en paréntesis: () => ({ id: 1, activo: true }).

Lección 06 / Renderizado de Listas

Métodos Puros: .map() y .filter() para UI

Reto 3 en Aula

En JSX, la forma estándar de mostrar cualquier colección de datos (usuarios, productos, transacciones) es transformar el array con .map().

.map(callback)

Devuelve un nuevo array del MISMO tamaño con cada elemento transformado.

.filter(callback)

Devuelve un subconjunto con los elementos que cumplan una condición booleana.

⭐ La Prop "key": Cuando mapees elementos en React, cada elemento raíz debe llevar key={item.id} para que el algoritmo de reconciliación de React no redibuje el DOM innecesariamente.
ListaProductos.jsx JSX en Acción 
// Filtrar solo productos en stock y proyectar a componentes:
const productosDisponibles = catalogo
  .filter(p => p.stock > 0)
  .map(p => (
    <div key={p.id} className="tarjeta">
      <h4>{p.nombre}</h4>
      <p>${p.precio}</p>
    </div>
  ));

Lección 07 / Acumuladores Complejos

Dominio de .reduce(): Balances y useReducer

Reto 4 en Aula

Mientras que map y filter devuelven nuevos arreglos, .reduce() permite condensar una colección en cualquier estructura: un número, un objeto agrupador, un mapa de totales, o un estado global.

Firma del método: array.reduce((acumulador, elementoActual) => { ... }, valorInicial)

En el Reto 4, calculamos el balance financiero completo de un pedido: subtotal bruto, descuentos aplicados, base gravable e IVA calculado.

ejemplo-reduce.js 
// Calcular total a pagar en un carrito
const totalNeto = carrito.reduce((acc, item) => {
  return acc + (item.precio * item.cantidad);
}, 0);

console.log(`Total a pagar: $${totalNeto}`);

// Conexión con React: useReducer sigue exactamente
// la misma firma conceptual: (state, action) => newState
🎯 Ejercicio en Aula 07: Balance Financiero con IVA 19% (Reto 4) Reto 4 en Vivo (10 min)

Reto para el aprendiz: A partir de una lista de órdenes con precio, cantidad y porcentaje de descuento, calcula con un solo .reduce() el balance total: subtotal bruto, descuentos aplicados, base gravable e IVA 19%. 

const balance = items.reduce((acc, item) => {
  const bruto = item.precio * item.cantidad;
  const desc = bruto * (item.descuento || 0);
  acc.subtotal += bruto;
  acc.descuentos += desc;

balance.iva19 = Math.round(balance.baseGravable * 0.19);

Lección 10 / Peticiones de Datos

Async / Await con Control Robusto de Fallos

Reto 5 en Aula

Toda interacción con bases de datos o servicios externos en la nube toma tiempo. Con async/await escribimos código asíncrono que se lee secuencialmente como sincrónico.

❌ Nunca olvides el bloque try / catch:

Si la red se cae o el servidor devuelve error 500 y no hay catch, la aplicación en React se congela o lanza una excepción fatal no controlada.

En el Reto 5 implementamos un Pipeline Seguro con Fallback: si la API falla, la función devuelve datos seguros por defecto y no rompe el flujo del cliente.

consumo-api.js Patrón Profesional 
async function cargarDatosServidor(endpoint, fallback = []) {
  try {
    const res = await fetch(endpoint);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    return { exito: true, data };
  } catch (err) {
    console.error("Error al cargar:", err.message);
    return { exito: false, data: fallback };
  }
}

Lección 11 / Rendimiento Concurrente

Concurrencia: Promise.all() y Promise.allSettled()

Dashboards React

Promise.all([p1, p2, p3])

Ejecuta todas en paralelo. Si UNA SOLA falla, toda la promesa se rechaza de inmediato (todo o nada). Ideal cuando todos los datos son indispensables.

Promise.allSettled([p1, p2, p3])

Espera a que todas terminen, sin importar si triunfaron o fallaron. Devuelve el estado de cada una (fulfilled o rejected). Perfecto para sincronizar múltiples microservicios.

// Cargar en paralelo sin bloquear:
const [usuarios, productos, ventas] = await Promise.all([
  fetch('/api/usuarios').then(r => r.json()),
  fetch('/api/productos').then(r => r.json()),
  fetch('/api/ventas').then(r => r.json())
]);
